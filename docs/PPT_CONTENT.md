## 第 02 页｜开发背景 · 0:10–0:55

**上屏文字**

用武汉两日游作例子，从选地点到改路线，哪一步最费事？

| 现实场景 | 具体痛点 | TripFlow 的做法 |
| --- | --- | --- |
| 查到黄鹤楼、户部巷和昙华林，想排进两天 | 地点在地图里，安排在备忘录里，要反复复制和核对 | 地图与行程并排，拖动标记即可把地点安排到具体日期 |
| 担心第一天太赶，临时把昙华林移到第二天 | 原来查过的交通时间失去参考价值，还要重查两天路线 | 卡片可跨天移动，受影响的路线按新顺序计算，时间轴跟着更新 |
| 隔几天接着规划，或想把计划发给同行的人 | 难找回最新版本，别人也不方便在多处查阅 | 当前浏览器自动保存，可重开旅行记录，也可导出可读行程 |

**画面**：中间放“原来的操作”与“在 TripFlow 中的操作”两列。突出一张昙华林卡片从地图落入日期的截图。

**口播**：“假设我在排武汉两日游。找到黄鹤楼、户部巷和昙华林后，我通常还要切到备忘录，把地点抄进去，再回来查交通。如果发现第一天太赶，临时把昙华林挪到第二天，两天的路线都得再核对。我的做法是把地图和日程放在同一个页面，看到地点就拖进某天，跨天移动后再根据新顺序计算路线和时间。隔几天回来，浏览器能恢复上次的安排，也能导出一份行程给同行的人看。”

## 第 03 页｜概要设计 · 0:55–1:15

**上屏文字**

- **当前规划**：左侧每日行程，右侧地点探索与地图。手机可切换两种视图。
- **旅行记录**：打开不同旅行，按城市、年份和状态筛选，展开中国足迹地图。
- **应用结构**：React 组织界面，Zustand 管理编辑状态，高德提供在线地图服务，localStorage 保存在当前浏览器。
- **开发与构建**：HTML、CSS、JavaScript + Vite。

**画面**：用两张截图对照规划页和记录页。下方画简图“界面操作 → 行程状态”，从状态引出“地图与道路更新”和“本地保存”两条箭头。

**口播**：“应用分为当前规划和旅行记录两个入口。规划页负责安排每天去哪里，记录页负责打开不同旅行和查看足迹。界面使用 React，编辑数据放在 Zustand 中。高德返回地点与道路结果，旅行数据保存到当前浏览器。”

## 第 04 页｜数据模型 · 1:15–1:35

**上屏文字**

| 对象 | 保存的信息 |
| --- | --- |
| Trip 旅行 | 城市、日期范围、旅行状态 |
| Day 日期 | 有序游览 ID、酒店、出发时间、分段交通方式 |
| Place 地点 | 名称、坐标、地图标记样式 |
| Visit 游览 | 引用的地点、这次的停留时长、预约与备注 |

**图示文字**：同一地点“湖滨 in77”可以被“午餐”和“晚餐”两次游览分别引用。日期通过有序的游览 ID 决定先后顺序。

**口播**：“地点和一次游览是两个对象。地点有固定坐标，一次游览有自己的预约、停留和备注。因此同一家餐厅一天可以去两次，移动其中一张卡片时，它的备注也会一起移动。”

## 第 07 页｜关键技术一：界面怎么搭建 · 4:55–5:35

**上屏文字**

| 前端技术 | 用在系统哪里 | 页面上看到的结果 |
| --- | --- | --- |
| HTML 与 JSX | 日期区段、表单、按钮，及导出预览的原生对话框 | 输入出发时间、展开交通明细、在弹窗里预览行程 |
| CSS Grid、sticky、媒体查询 | 规划页双栏、右侧地图和窄屏布局 | 桌面上行程与地图并列，长行程滚动时地图仍可见。手机可切换视图 |
| React 组件、Zustand | 日期容器、游览卡片、时间轴、地图及共享行程状态 | 日期或顺序改变后，相关组件根据同一份状态更新 |

**画面**：用一张规划页截图标出“日期容器”“地图栏”“交通面板”，每处配一个实际文件名。源码对应 `src/styles.css`、`src/components/Itinerary.jsx`、`src/state/tripStore.js`。

**口播**：“这门课的前端三部分在页面上都能看到。HTML 表单负责输入出发时间，原生对话框用于导出预览。CSS Grid 把行程与地图排成左右两栏，右侧地图用 sticky 保持在视野内，窄屏通过媒体查询适配。React 把日期、卡片和时间轴拆成组件，Zustand 保存共享行程状态，让编号和时间跟随编辑结果更新。”

## 第 08 页｜关键技术二：拖放与道路怎么联动 · 5:35–6:20

**上屏文字**

| 技术 | 实际用法 |
| --- | --- |
| JavaScript 原生拖放 + 高德 HTML Marker | 地图标记用 `DataTransfer` 传递地点标识。日期落点在放下后创建一次游览。 |
| dnd-kit | 在日期容器之间预览插入位置。提交后移动原游览 ID，保留备注和停留。 |
| 高德 Walking / Driving + JS 异步控制 | 每天拆成相邻路段。快速编辑时合并请求，并校验返回结果是否仍对应当前行程。 |

**画面**：一条流程“地图标记 → 日期落点 → 更新游览顺序 → 查询相邻路段 → 刷新路线与时间轴”。页脚可放源码定位 `src/drag/mapDrag.js`、`Itinerary.jsx`、`src/map/routeController.js`。

**口播**：“地图标记是高德地图里的 HTML 标签，我用 JavaScript 原生拖放传递地点标识，放到日期后创建一次游览。已有卡片由 dnd-kit 处理，只移动原游览，所以备注和时长跟着走。顺序提交后，系统按每天相邻地点调用高德步行或驾车服务。快速拖动会让旧请求失效，返回时再核对当前安排，避免迟到的旧路线覆盖新结果。”

## 第 09 页｜关键技术三：浏览器存储、导出与复用 · 6:20–6:55

**上屏文字**

- **localStorage**：按旅行 ID 保存、恢复，支持多份独立行程。
- **JSON 校验**：检查版本、坐标、唯一 ID 和引用，校验通过后写入。
- **HTML 与打印样式**：可读导出生成离线网页，PDF 由浏览器打印保存。
- **复用范围**：修改复用 MIT 高德路段请求与路径解析片段。TREK 与多日规划项目用于交互参考。

**画面**：左侧放“导入 → 校验 → 恢复行程”的简图，右侧放打印预览。页脚注明 `src/state/document.js` 和 `src/state/readableExport.js`，来源与许可见项目报告。

**口播**：“旅行保存在浏览器的 localStorage。导入 JSON 时先校验版本、坐标和引用，确认后才更新。可读导出用 HTML 呈现，用浏览器的打印样式保存 PDF。代码复用集中在 MIT 许可的道路请求片段，界面、拖放规则、路线调度和存档校验由本项目实现。”
