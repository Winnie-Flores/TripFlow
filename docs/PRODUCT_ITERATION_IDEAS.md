# TripFlow 后续产品改善建议

这份建议形成于 2026-11-10，依据当时的项目功能和 Trek 演示。2026-11-11 完成了前五项改进，其中地点分类收藏与旅行记录筛选合为一项。旅行复盘与多城市旅行仍列为后续方向。

## 当前主线与目标

当前主线已经闭环：新增旅行 → 选城市与地点 → 拖拽分日规划 → 安排酒店 → 真实道路联动 → 保存备份 → 历史记录与足迹。课程展示下一步更值得改善“安排是否合理、编辑是否放心、旅行后是否留得住”，而非继续铺开新业务。

| 优先级 | 功能 | 解决的问题 | 建议范围与验收 |
| --- | --- | --- | --- |
| P0 | 撤销 / 重做 | 拖错、删错地点或日期，只能重新安排 | 记录有限数量的本地编辑快照；覆盖重排/跨日/删除/酒店修改；撤销后道路按最新状态重算。切换旅行清空编辑历史，避免跨旅行误撤销 |
| P0 | 每段独立交通方式 | 现在整天统一步行或驾车，实际往往酒店到景点驾车、商圈内部步行 | 对每个相邻路段选择方式，保留“全日统一”快捷设置；地点重排后根据稳定的端点引用保留或失效旧选择。先完成步行/驾车，再考虑公共交通，后者需另核对服务支持 |
| P0 | 每日时间轴 | 知道路程和停留，但不知道一天是否排得下 | 自设出发时间，叠加已完成交通用时和停留，推算到达/离开；允许午晚饭或预约时间。道路失败时明确时间推算不完整；营业时间若缺可靠来源先支持手填，不做不可靠自动提示 |
| P1 | 可阅读的行程导出 | JSON 适合备份，难以直接给同伴或老师查看 | 增加打印版/PDF视图，包含每日顺序、酒店、备注和交通明细；导出明确完整/部分/无道路结果；不导出SDK或未经允许的离线地图瓦片 |
| P1 | 地点分类与收藏 | 商场、餐厅、景点越来越多，浏览与复用困难 | 地图/候选列表共用“景点、餐饮、购物、酒店”筛选；支持用户收藏和已安排筛选，提供一键添加。收藏与已去过分别管理，不能互相替代 |
| P1 | 旅行记录筛选与轻量统计 | 卡片数量增长后难查找，足迹缺少回顾感 | 按规划/已去过、年份和城市筛选；统计实际标记去过的城市数、旅行数，避免把候选地点或未来计划计入去过。点击地图城市与筛选状态联动 |
| P2 | 旅行复盘 | 完成旅行后只剩规划，缺少真实体验 | 旅行总备注、实际去过/跳过的游览、简单评分；照片以后再做，先解决本机容量、备份体积和隐私展示的问题 |
| P2 | 多城市连续旅行 | 现有一次旅行固定一个城市，不能自然表达杭州→苏州 | 需要调整Day与城市关系、搜索范围、足迹统计和跨城交通语义，改动较大；建议作为课程完成后的后续版本，不与当前单城模型混用 |

## 推荐顺序

先做撤销/重做，再做每段交通方式，最后做每日时间轴。这三项直接强化拖拽规划的核心价值。若以课程展示为近期目标，可把“可阅读的行程导出”提前到第二项，演示和提交都更实用。

本轮中国足迹地图已经实现区域灰底、城市边界填色与全览；后续可以补充年份/状态筛选，但无需现在扩展到全球地图或复杂轨迹动画。继续保持项目既定范围，不增加预算、AI、登录与多人协作等独立系统。
