# 旅序 TripFlow · 需求与验收

更新：2026-11-07。依据：用户总约定、阶段 0 指令及根目录 `TripFlow_Stage_Prompts.md`。初始目录仅有该提示词文件，无应用代码、docs 或历史验收记录；提示词提及的原始 Brief 不在本地，本次不声称重新读过。

## 目标与边界

Web 课程作业，展示不超过 8 分钟。核心流程：选城市 → 热门景点地图 → 地图标记直接拖入每日行程 → 搜索其他地点并编辑标记 → 同日排序/跨天移动 → 真实道路随顺序更新 → 刷新恢复。

React + JavaScript + 原生 CSS + Vite；高德 JS API 2.0；原生 HTML 拖放用于地图来源，dnd-kit 用于行程列表；Zustand + localStorage。无 TypeScript、大型 UI 库、业务后端、数据库。预算、AI、登录等不在范围内。阶段 0 只建立基线，安装依赖不等于功能完成。

## 数据契约

- Place：稳定 ID、来源 ID、名称、地址、城市、GCJ-02 经纬度、标记形状和颜色。
- Visit：唯一 ID、placeId、备注、停留时长；同一地点可有多次游览。
- Day：唯一 ID、日期、visitIds；visitIds 是唯一顺序依据，不增加 sortOrder。
- Trip：旅行名、城市、开始日期、天数与日期顺序。
- 地图拖入新增 Visit；列表拖动保留原 Visit ID；同日地点重复提示，跨日允许；拖拽不修改坐标。

## 验证证据规则

构建/静态检查不能代替浏览器交互；模拟 SDK 验证不能代替高德真实鉴权与服务联调。演示模式必须标注，示意线不可冒充道路。阶段 0 页面为空态；阶段 1 无配置时为明确标注的坐标演示平面，不显示道路、距离或交通时长。

## 外部配置

高德 Web 端（JS API）Key、安全密钥 securityJsCode、控制台允许当前访问域名，以及可访问高德服务的网络/WebGL 浏览器。变量名见 `.env.example`；修改后重启开发服务。`VITE_` 值可被浏览器读取，环境文件忽略只防止意外提交，并不提供前端保密。

## 阶段 1 实际范围

阶段 1 时 Place/Visit/Day 模型已落地，单日排序仅修改 visitIds；date 当时为 null，阶段 2 已升级为实际日期。仅两个核验地点；支持地图原生拖入空天、首尾插入，dnd-kit 同日排序，按钮安排/上移/下移/删除作为补充。真实道路适配已实现，当前以单路段为主；完整多天、请求限流/分段统计在后续阶段。

验收区分：单元逻辑与演示浏览器流程已验证；真实 SDK 通过请求边界模拟验证了适配与生命周期；D1/R1 的真实高德拖放及道路验收仍待真实配置。当前不实现自动保存，页面明确提示刷新重置。

## 阶段 2 范围、规则与验收边界

- Trip 保存 id/name/city/startDate；天数仅从 days.length 派生，不维护第二套 dayCount 或 sortOrder。支持 1—30 天。Day.id 与 Visit.id 稳定，日期标签按 days 数组顺序计算。
- 开始日期固定，插入/删除天后重新从开始日连续标注日期。例如 12/30=A、12/31=B，在第 2 天前插入后为 12/30=A、12/31=空、1/1=B；删除空天后 B 回到 12/31。已有游览不因日期重编号而重建。
- 删除非空日期、缩短后丢弃尾部游览、带内容切城和重建均先确认；取消不改变数据；最后一天不能删除。切城清除旧城市地点与游览，避免混入。城市可编辑，现阶段仍仅武汉有两个预设地点；其他城市显示待接入提示，不冒充已完成阶段 4 的搜索/定位。
- 地图拖入在任意日期新建 Visit；列表跨天/同日移动原 Visit。不同日期可安排同一 Place，移入已经有同 Place 的一天则拒绝。原生与 dnd-kit 事件不混用。
- 拖动只展示浮层与插入提示，不写正式 days；松开后一次提交。取消/无效区域恢复原状；提交时核对结构 revision，拒绝拖动期间发生结构变化的旧操作。
- 备注最多 2000 字；停留时长 0—1440 整数分钟，失焦保存到该 Visit，跨天保留。备注/时长变化不重新计算道路。选中日期或移动完成的目标日期决定地图编号与当前道路，不连接跨日首尾。
- 逻辑/演示浏览器与模拟 SDK 验证结果见 PROGRESS；真实高德鉴权、地图平移冲突和实际道路仍待配置联调。刷新恢复与导入属于阶段 5，当前刷新仍重置。


## 阶段 4 当前规则（替代阶段 1/2 当时的地点限制）

- 武汉默认 12 个核验 POI；其他城市由 DistrictSearch 核对名称、adcode、中心点，地图定位到新城市，PlaceSearch/AutoComplete 限定该城市。支持地级市与四直辖市；无配置演示只编辑城市文本，不冒充在线核验。
- 切城保留开始日与天数，清空旧游览与候选，重新生成旅行/日期 ID；有游览或搜索候选时先确认。输入核对期间再次修改字段或查询后，旧结果不能提交。
- 稳定高德 POI ID 为去重依据；同名不同 ID 保留。缺坐标仅按同 ID 查详情，缺 ID、坏坐标、不匹配详情或异城结果明确反馈，不以同名第一条猜测。
- 地点 shape/color/category 共用，地图和 Visit 渲染同一 Place 的 SVG；编号与形状分开。搜索新增默认 star，重复选择不覆盖用户已改样式；仅更新允许样式字段，不能借样式编辑改坐标。
- 搜索类请求串行/1100ms 最小起点间隔，450ms 输入防抖；清空/新输入/切城/选中/卸载同步失效旧代际。只接受当前查询结果；没有离线搜索缓存或持久化 POI 历史。
- 当前演示是明确标注的地点卡片平面，非地理比例，不绘制虚构道路。刷新仍重置，持久化待阶段 5。


## 阶段 5 当前规则（替代前文“刷新重置”的历史限制）

持久化 schemaVersion=1：trip、cityInfo、Place/Visit/Day 数组与用户偏好 settings；运行时的 SDK/DOM、道路请求和几何、搜索响应、拖动预览与提示不保存。250ms 合并保存，页面隐藏/离开立即 flush；恢复及每次合法导入使运行时代际失效并重新计算道路。

导入上限 2 MB、30 天、500 地点、3000 游览。校验字段/未知字段、ID 唯一性及来源匹配、坐标与样式、城市行政码、连续日期、每次游览恰属一个日期且引用存在、同日地点不重复。先校验再确认原子替换；同 ID 导入也刷新编辑器/搜索/地图，非法数据不改当前旅行。损坏/未知版本的旧本机存档不自动覆盖，存储拒绝/超额提供显式状态和备份入口。

手机切换行程/地图，隐藏视图不可交互或键盘聚焦，地图不因切换销毁，显示后适配所选行程视野。桌面维持左行程右地图，设置/配置可折叠，提供保存/加载/错误/空态及统一焦点。实际验证区分状态逻辑、模拟 SDK、真实在线服务与截图检查。


## 用户授权迭代：多旅行历史规划（2026-11-08）

在原单旅行范围上增加顶部导航、旅行卡片记录页和新增旅行。每次旅行拥有独立 Trip/Day/Visit/Place 数据与用户样式；新增杭州、切回武汉、继续编辑与刷新均不能丢失或混入其他旅行的数据。支持名称/城市查找、卡片打开、单条导出、删除确认，当前编辑记录不可直接删除。

集合 schemaVersion=1、activeTripId、records（document/createdAt/updatedAt），保留单旅行 v1 JSON 格式。初次迁移旧单旅行存档并保留旧原文，优先新集合，坏集合不自动回退到过时备份。最多 50 条/合集 4 MB，超额不淘汰；失败不破坏原存档。导航至记录页前归档当前内容；切换时失效旧运行时代际并重挂独立地图/搜索。新增和切城/重建保留原旅行，更新前述“只保留一个旅行”的限制。不引入后端、登录或云同步。
